# CLAUDE.md

Always-loaded contract for working in this repo: the invariants that bind
every change, the verification commands, the conventions, and the working
agreement. Keep it lean — it loads on every turn.

The explanatory bulk (module map, CLI reference, configuration reference,
the UK-tax pipeline, extension recipes) lives in
[docs/architecture.md](docs/architecture.md); read it on demand. The durable
*why* behind load-bearing choices is in

maps every doc.

## What this is

`banking-pipeline` ingests banking correspondence (PDFs + one Revolut-CSV
side path), classifies each document by language → bank → doctype, extracts
the accounting-relevant fields, and emits [beancount](https://beancount.github.io/)
text. Single-user, built around Pictet (Luxembourg + Madrid) plus a Vanguard
UK Stocks & Shares ISA. Adding a bank is a **data-only** change.

## Invariants

Hard constraints that must hold on **every** change:

- **Licence hygiene.** Every runtime dep is MIT / BSD / Apache-2.0 except
  `python-stdnum` (LGPL-2.1+, dynamic linking only). **Do not add
  `PyMuPDF`** (AGPL-3.0) and **do not `import beancount`** (GPL-2.0) — output
  is plain text, validation shells out to the `bean-check` binary. The
  README's "Libraries and licenses" section is the source of truth before
  adding any dependency.
- **No `Equity:Uncategorized` in generated output.** It is the deliberate
  placeholder the strict-mode dispatch was built to eliminate (see below).
  Find the right account in `writer/format.py` + the per-shape builder, or
  extend `Transaction` with a new field and a builder branch.
- **Never re-parse beancount for tax.** The `*.transactions.jsonl` sidecars
  are the load-bearing substrate `tax-report` consumes; all section-104 /
  GBP math happens there, never from ledger text. Beancount's booking
  methods do not implement UK matching rules.
- **One ISA tax-exempt choke point.** `tax-report` filters
  `[tx … if not tx.is_tax_exempt]` once, right after loading the sidecars,
  before any `compute_*` / `match_history`. Don't add per-report wrapper
  filters.
- **The model invariant `gross_income − withholding_tax == amount`** (within
  a cent) is enforced in `Transaction`'s `@model_validator`. Don't paper
  over a break — fix the template.
- **Don't hand-edit generated ledgers.** `data/portfolio.beancount` is
  generated by `portfolio_aggregate` (owns operating currency, booking
  method, account opens + closes). Hand-curated overrides go in
  `main.beancount`. Close directives are aggregate-only — don't re-add a
  close to `ingest`.
- **`main.beancount` (the `bean-check` root) must declare**
  `option "booking_method" "FIFO"` and `operating_currency`: beancount reads
  those options only from the root file. Omitting `booking_method` drops
  booking to `STRICT` and every `{}` switch-out matching >1 lot fails.
- **PII / personal figures never get committed.** Scrub fixtures to the
  allow-listed placeholders, and never cite real amounts, balances,
  gains/losses, or holdings from the gitignored `data/` / `reports/` in
  committed docs, messages, or backlog/changelog entries (see
  [Anonymisation](#anonymisation-and-the-pii-guard)).

## Tech / build

- Python **3.14** strict (`requires-python = ">=3.14"`, `mypy strict`,
  `target-version = "py314"`).
- Dependency manager: **uv**. Use `uv run …` for every command — do not
  invoke `python`/`pytest`/`mypy`/`ruff` outside `uv run`, and do not
  `pip install`; edit `pyproject.toml` and let `uv sync` resolve.

## Architecture (the must-know shape)

```
import ──► dated archive ──► PDF ──► extract ──► classify(lang→bank→doctype)
                                        ──► fields ──► writer ──► beancount (+ jsonl sidecar)
```

Each classify/extract stage is **hybrid**: deterministic rules first; the
Claude LLM fallback only fires below `rule_confidence_threshold` (default
`0.75`) and is skipped silently when `BANKPIPE_ANTHROPIC_API_KEY` is unset.
The default facade is `LayeredClassifier` (language → bank → doctype). The
UK-tax pipeline is **separate** and reads the sidecars, not the ledger.

The full module map, data flow, and per-command behaviour are in
[docs/architecture.md](docs/architecture.md).

## Domain conventions

- `DocumentType` values stay in the **issuer's own vocabulary**
  (`SWITCH_SALIDA`, `COMPRA`, `REEMBOLSO`, `PAGO_INTERNA`, …) — don't
  anglicise them. Each enum value's docstring documents its distinguishing
  PDF-text markers; read it before authoring rules or templates. `Language`
  values are ISO 639-1 (`en`, `es`) + `unknown`.
- `NO_OUTPUT_DOCTYPES` (in `models.py`) is the single source of truth for
  "this doctype legitimately emits zero transactions" — both the writer and
  the extractor consult it. Periodic statements and paired-advice openings
  belong here.
- `Transaction` is the canonical row. `currency`/`amount` is the **cash-leg
  currency**; `security_currency` is the **trade-execution currency** (they
  differ on FX trades, where `subtotal_security` + `fees` carry the
  pre-conversion amounts). `Transaction.is_fx` is the single branch point.
- Internal cross-currency transfers and self-to-self payments are modelled
  as **one** `Transaction` carrying both legs (`counter_currency` /
  `counter_amount`, or `gross_amount` / `counter_account`), never two
  balanced against `Equity:Uncategorized`.

See [docs/architecture.md](docs/architecture.md#the-domain-model) for the
full `Transaction` field set (the UK-tax substrate, etc.).

## Working in this repo

- **Prefer editing rules / fixtures / templates over the pipeline core** —
  the architecture is intentionally data-driven, and most "the classifier
  got it wrong" or "the extraction missed a field" issues resolve there.
- **Adding a bank is data-only** — `BankId` + `BankRule` + ruleset +
  `templates/<bank>/` package + `BankWriterProfile` + fixtures. The full
  6-step recipe is in
  [docs/architecture.md](docs/architecture.md#adding-a-new-bank).
- **Don't run the LLM fallback paths in tests** — they need
  `BANKPIPE_ANTHROPIC_API_KEY` and are non-deterministic. The rule/template
  paths are the test surface.

## Fixtures and tests

Fixtures live at `tests/fixtures/<language>/<bank>/<doctype>[.<tag>].txt`.
The folder/file names **must match** the enum values exactly — that's how
`conftest.discover_fixtures` derives the expected classification without a
manifest. Beancount goldens sit next to their text fixtures with a
`.beancount` suffix; `tests/test_render_goldens.py` re-renders and diffs.

When adding a doctype: dump text with `extract-text --show-rules`, add a
`Rule` and a fixture, then a template, then a golden. The parametric suites
in `test_pictet_fixtures.py` and `test_language.py` pick up the new fixture
automatically and assert each stage clears `rule_confidence_threshold`.

## Anonymisation and the PII guard

Fixtures are scrubbed of **personal identifiers** before commit — name, NI
number, DOB, home address, IBANs are replaced; security names and trade
amounts are kept (needed for goldens, not identity PII). Account numbers use
**allow-listed placeholders**: Pictet portfolio body `999999` (most EN
fixtures), `123456` (ES + buy/sell-shares), or `000000` (numbers-only
inputs); Vanguard ISA `VG0000000`; NI `AB123456C`. Mirror an existing
sibling when adding a fixture from a real PDF.

`scripts/check_pii.py` enforces this as a **pre-commit guard** (install once:
`git config core.hooksPath scripts/git-hooks`); `python3
scripts/check_pii.py --all` audits the whole tree. It catches *identifiers*,
not *derived figures* — so the "never cite real figures" invariant above is
on you, not the guard. Details:
[docs/architecture.md](docs/architecture.md#anonymisation-and-the-pii-guard).

## Strict-mode dispatch (the footgun)

`HybridExtractor` dispatch when a registered template returns `[]`:

- Doctype in `NO_OUTPUT_DOCTYPES` → return `[]`. Expected.
- No template registered → fall through to regex / LLM.
- Template registered but empty → log WARN, return `[]`, **skip** the
  fallback. Under `strict=True` raise `TemplateExtractionError`.

The skip is deliberate: falling through historically papered over template
regressions with `Equity:Uncategorized` placeholders. `ingest --strict` and
`rebuild --strict` turn this on (and `rebuild --strict` also escalates
`bean-check` warnings + reconcile coverage gaps to failures). Rationale:
[docs/design-decisions.md](docs/design-decisions.md).

## UK tax

The tax pipeline reads the sidecars, applies UK tax-year bounds + section
104 matching, and writes the SA108 / SA106 CSVs + the CGT loss-carry-forward
chain. The ISA choke point and the `gross_income − withholding_tax ==
amount` invariant are above. Reporting status / per-ISIN flags
(`deeply_discounted`, `distributions_as_interest`), the rate-coverage
(`RateGap`) mechanism, the AEA / loss-carry-forward chain, and the residence
/ FIG corrections are all documented in
[docs/architecture.md](docs/architecture.md#the-uk-tax-pipeline). Not tax
advice — verify against HMRC guidance.

## Conventions

- **Spelling:** keep `DocumentType` / doctype names in the issuer's own
  vocabulary (above); prose is British English.
- **Code style:** point at `ruff` — don't restate its rules. Python 3.14,
  `mypy strict`.
- **Commits:** Conventional Commits, imperative mood, one concern per
  commit. Stage explicit paths (`git add <path>`), never `git add -A`.
- **Layout:** the pipeline is data-driven — extend rules / fixtures /
  templates before the core.

## Working agreement

- **Plan first when it matters.** For any change touching more than ~3
  files, a refactor, or anything affecting an invariant above: enter plan
  mode, get the plan approved, write it to `docs/plans/<name>.md`, then edit.
  Small local changes skip this.
- **One plan file, status folded in.** Each plan is a sequence of Stages
  worked in order; status lives in the same file. After a compaction or
  restart, resume from the active plan.
- **One session, one worktree.** Never run two sessions in the same working
  directory. Stage explicit paths; commits and pushes are reviewed by me.
- **Review before merge.** Run the `code-reviewer` subagent
  (`.claude/agents/`) on the diff before any merge to `main`. There is no
  second reviewer; this is it.
- **Verify, don't assume.** Run the commands above and check against the
  Definition of Done (`.claude/rules/definition-of-done.md`) before
  reporting a change done.
